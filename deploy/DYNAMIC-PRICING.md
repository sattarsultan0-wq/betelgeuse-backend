# Динамическая стоимость генераций

Актуальные правила заменяют прежнюю наценку 40% и ограничение запуска только ADMIN. PostgreSQL, Prisma, баланс `User.generationCredits`, очередь и механизм возвратов остаются прежними. Новых таблиц и миграций Prisma нет. Платежи и покупка подписок не реализованы.

## Конфигурация

- `src/pricing/providers/higgsfield.json` — единственный источник себестоимости моделей. Его структура и значения в этом изменении не менялись. `null`, ноль и некорректное значение запрещают запуск; Seedance с `billingReviewRequired` остаётся заблокирован.
- `src/pricing/pricing-policy.js` — все коэффициенты в одном месте: стандартная наценка `0.8`, наценки платных тарифов, стоимость кредита `0.01 USD`, округление вверх, цены подписок в KZT и отдельные маркетинговые проценты. Free использует стандартную наценку из policy.
- `src/pricing/subscription-discounts.js` — выбор действующей подписки и применение точного коэффициента скидки к стандартной сумме.

| Тариф | Цена в месяц | Итог от себестоимости API | Отображаемая скидка |
| --- | --- | --- | --- |
| Free | 0 ₸ | ×1.8 | 0% |
| Basic | 4 990 ₸ | ×1.6 | 11% |
| Creator | 14 990 ₸ | ×1.4 | 22% |
| Pro | 26 990 ₸ | ×1.2 | 33% |

Модуль скидок получает неокруглённую стандартную сумму и применяет точное отношение `(1 + tierMarkup) / (1 + standardMarkup)`. Коэффициенты и деление представлены BigInt; единственное округление — `creditCeil` в `exact-money.js`. Стандартные кредиты округляются отдельно только для отображения зачёркнутой цены. Округлённая стандартная цена не участвует в расчёте скидки.

## Существующие подписки

Используются `Subscription` и связанный `Plan` из PostgreSQL. Имя `Plan.name` сопоставляется с Free/Basic/Creator/Pro без учёта регистра и крайних пробелов. Неизвестный старый тариф сохраняется в ответе billing, но даёт стандартную стоимость. STARTER не переименовывается автоматически в Basic.

Подписка должна иметь `status = active` и `expiresAt > now`. Значение `expiresAt = null` сохраняет существующий смысл бессрочной активной подписки. При нескольких активных записях выбирается самый высокий известный тариф, при равенстве — первая по ID. Если подписки нет, она истекла или отменена, применяется Free. Изменение `planId` или имени связанного плана учитывается при следующем расчёте. Источник пополнения баланса не влияет на скидку.

Для применения скидок назначайте существующему пользователю подходящую запись `Subscription` через доверенный серверный процесс. Цену `Plan.price` храните в KZT согласно таблице. Публичные карточки получают предложения из центральной конфигурации через `GET /api/pricing/plans`; endpoint не создаёт подписки и не принимает оплату.

## Контракт оценки и подтверждения

`POST /api/generations/estimate` сохраняет прежние поля и добавляет `baseCredits`, `subscriptionPlan`, целый маркетинговый `discountPercent` и непрозрачный `priceConfirmation`. Оценка персональная и требует существующей авторизации. У трендов есть `POST /api/trends/estimate` с `{ "trendId": "..." }`; приватный промпт не раскрывается.

При создании передавайте `priceConfirmation` последней показанной оценки вместе с прежним body и `Idempotency-Key`. Это отпечаток пользователя, роли ADMIN, параметров, текущей подписки и версии цены. Перед списанием backend повторно читает подписку и рассчитывает цену внутри транзакции под блокировкой аккаунта. Переданный клиентом размер списания не используется.

При отсутствии или несовпадении подтверждения оплачиваемого запроса сервер возвращает `409 PRICE_CHANGED`, локализуемое сообщение и безопасный `currentQuote`. Списания и нового задания нет. Frontend обновляет оценку и ждёт повторного нажатия Generate. Автоматического запуска по новой цене нет. Смена роли ADMIN также меняет подтверждение, чтобы ранее показанное нулевое списание не превратилось в платное.

Старые ADMIN-клиенты могут создавать бесплатные тестовые задания без `priceConfirmation`: сохранена совместимость для нулевого списания. Если подтверждение передано, оно проверяется и для ADMIN. Наличие корректной стоимости модели обязательно в любом случае.

Повтор одного принятого ключа возвращает существующую генерацию до проверки нового тарифа. Подтверждение цены исключено из хеша параметров задания: обновлённая оценка не создаёт конфликт с тем же самым заданием. Изменённый промпт/модель/референсы под уже принятым ключом вызывают конфликт.

`Generation.costEstimate` хранит снимок итоговых и стандартных кредитов, тарифа подписки, скидки, версии тарифа и внутренних денежных сумм. `quotaCost` — фактическое списание. История использует снимок, воркер не пересчитывает стоимость. API выдаёт только разрешённые публичные поля без себестоимости и наценок.

Guarded decrement и уникальный `(userId, idempotencyKey)` сохраняются. Конкурентные запросы сериализуются блокировкой пользователя, отрицательный баланс запрещён. Безопасный отказ возвращает ровно `quotaCost` один раз через существующий механизм lease/status/quotaRefunded. При неопределённом результате отправки провайдеру сохраняется прежняя сверка вместо автоматической повторной оплаты или возврата.

## Деплой и проверка

1. Примените ранее существующие миграции (`npm run db:migrate`), если они ещё не применены. Новая миграция не требуется, снимок расширяется внутри существующего JSON.
2. Разверните backend и frontend согласованно: оплачиваемые запросы требуют нового подтверждения оценки. Перезапустите также процесс воркера.
3. Новых переменных окружения нет; нужны существующие PostgreSQL, авторизация, Higgsfield и R2. Ключи и секреты не менялись.
4. После правки цен/коэффициентов перезапускайте все экземпляры API и воркера. JSON читается один раз при запуске; смешанные версии серверов могут отклонять подтверждения. Версия учитывает себестоимость, модельные конфигурации, policy и конфигурацию тарифов подписок.
5. Проверки: `cd backend && npm run test:db`; `cd frontend && npm test` и `npm run build`. PostgreSQL-тесты создают отдельный временный кластер, не меняя базу разработки. Провайдер и R2 в тестах подменены; платные генерации не выполняются.
